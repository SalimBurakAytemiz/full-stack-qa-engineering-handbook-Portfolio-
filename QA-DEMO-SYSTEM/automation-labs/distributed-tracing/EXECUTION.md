## What this run actually proves

- A real `traceparent`-style header, generated by the downstream
  service and sent as a real HTTP request header, is correctly read
  back by a genuinely separate upstream `node:http` server process
  (a different server instance on a different real loopback port) —
  the propagation crosses a real network hop, not a same-process call.
- The resulting span tree, built entirely from what each real side
  independently recorded to a shared in-memory collector, has the
  exact shape a tracing system promises: one root, one child, correct
  parent linkage.
- Repeating the real request produces a genuinely new, independent
  trace id each time — trace identity isn't accidentally shared
  across requests.

## Scope and honesty notes

- Loosely modeled on the W3C `traceparent` format — not a claim of
  full W3C Trace Context spec conformance. See `README.md`'s "Scope
  boundary" section.
- In-memory collector only — no real export to a tracing backend
  (Jaeger, Zipkin, OTLP).
- Self-contained — never touches the real backend (`backend/src/`).
- No real defect was found while building this lab; both the unit
  tests and the aggregate run passed cleanly on their first real
  execution. This is stated plainly rather than inventing a "mistake"
  for `COMMON-MISTAKES.md` where none occurred.
